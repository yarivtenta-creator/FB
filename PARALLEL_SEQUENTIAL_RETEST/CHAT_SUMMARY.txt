1. המשימה המקורית
--------------------------------------------------------------------
המשתמש ביקש להריץ retest של שיטת תכנון מקבילית (parallel planning)
בתוך סשן ענן אחד. המטרה: להמיר בקשה ("Build a Desktop Organizer
module") ל-Build Package עבור Claude/Codex/מפתח - בלי לבנות שום דבר.

התהליך פורק ל-5 שלבים + דוח סיכום:
  PROJECT_A (1-2)  Intake & Understanding
  PROJECT_B (3-4)  Scope & Missing Inputs
  PROJECT_C (5-6)  Roles & Knowledge (references בלבד)
  PROJECT_D (7-8)  Tools & Risks (safe-mode, פעולות אסורות)
  PROJECT_E (9-10) QA & Final Package (ready/blocked)
  RESULT           דוח retest שעונה על 8 שאלות

חוקי סיווג בכל הקבצים:
  CONFIRMED / ASSUMED FOR RETEST / PROPOSED DEFAULT /
  UNKNOWN / OWNER REVIEW REQUIRED / DEFERRED

--------------------------------------------------------------------
3. תובנה מרכזית
--------------------------------------------------------------------
המטרה האמיתית הייתה ללמוד להריץ משימות במקביל (parallel), לא בטור.
הסשן הזה בפועל רץ בטור (series): משימה אחת, קבצים נכתבו אחד אחרי השני.
רק השיטה שנבדקה מדמה מקביליות - הביצוע היה סדרתי.

דוח RESULT: השיטה עובדת ובטוחה לתכנון, אבל לפני שימוש אמיתי צריך:
  1. להחליף upstream מדומה ב-upstream אמיתי
  2. להוסיף שלב integration/reconciliation
  3. לאכוף מקרא סיווג אחיד

--------------------------------------------------------------------
4. איך מריצים משימות במקביל ב-Claude Code
--------------------------------------------------------------------
הסשן הראשי רץ בטור, אבל יכול להשיק כמה subagents בבת אחת
(מספר קריאות Task בצעד אחד):
  - כל subagent = הקשר מבודד, בלי קשר לאחרים חוץ מהטקסט שנמסר
  - צימוד למודל: Haiku=טקסט פשוט, Sonnet=בנייה/עיצוב/קוד, Opus=חשיבה כבדה
  - מגבלות: ~10-16 רצים בו-זמנית; כל subagent מחזיר רק הודעה סופית

גישה A - Flat parallel:
  פרומפט אחד -> 10 משימות עצמאיות במקביל, כל אחת עם רמז מודל.
  מתאים למשימה בודדת (מייל, עריכת תמונה, סיכום).

גישה B - Parallel + sub-agents:
  כל משימה כבדה מתפצלת לתפקידים (build/design/copy/QA) שרצים
  במקביל, ואז MERGE לכל משימה. מתאים ל-landing page / Shopify.

המלצה: ברירת מחדל Haiku; Sonnet רק לבנייה/עיצוב/קוד; Opus רק
לארכיטקטורה. אפשר לערבב. הוצע ליצור פקודה קבועה /parallel-missions.
