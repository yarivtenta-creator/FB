## 1 ▶ ROAST (pressure-test an idea/plan)
> Run ROAST on the attached idea/file. Spin up an adversarial council — contrarian (fatal flaw), expansionist (biggest upside), first-principles (does the value exist), deep researcher (web: substitutes/competitors/pricing), buyer (role-play the real customer). Each scores /10. Then a judge verdict: green-light / reshape / kill, with confidence, biggest risk, biggest upside, scores, and the single cheapest 48-hour test. If reshape, give the narrower version to build.

## 2 ▶ VERIFY (prove it works)
> Run VERIFY on the attached file/folder/build. "Looks done" ≠ "works". Check integrity/consistency (and checksums if present); if code or a page, run it, screenshot desktop+mobile, click through, break it with edge cases; if a doc, trace every claim to a source and check completeness. Report PASS/FAIL per check with real evidence (not "I checked"), plus a definition of done and an honest list of anything thin/missing/broken.

## 3 ▶ GOAL (build/finish the pieces)
> Run GOAL on the attached file/folder. Define an objective finish line (measurable "done"). Fan out parallel sub-agents, one per deliverable, each own context and own file. A separate evaluator (not the builder) checks the conditions — Claude can't declare itself done. Final verification pass: open each file, fix thin/generic parts, show the finished set. Tell me the finish line and whether every condition was met.
