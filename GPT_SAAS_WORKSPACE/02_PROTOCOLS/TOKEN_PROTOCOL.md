# TOKEN_PROTOCOL

How executors avoid wasting tokens.

## Read discipline

- Read `PROJECT_STATE.md` only. Read `SOURCES/`, `ARCHIVE/`, or raw imports **only** when the
  current `NEXT_ACTION` explicitly requires them.
- Never read full chat transcripts. Read the curated extract in `SOURCES/` instead.
- Never re-read a file you just wrote to verify it.

## Write discipline

- Write the deliverable once, to the correct location. Do not paste it into chat too.
- Keep `PROJECT_STATE.md` under 400 lines; roll old AUDIT/HANDOFF lines into
  `ARCHIVE/STATE_HISTORY.md`.
- Extracts capture only: decisions made, assets produced, open questions. Never the whole
  transcript.

## Stop conditions

- Stop when `NEXT_ACTION` is done and the state is updated. Do not keep going "to be thorough".
- If blocked, log the blocker with a default and stop that thread — do not burn tokens looping
  on a decision only the operator can make.
